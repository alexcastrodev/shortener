# Languages (i18n)

The frontend ships `en` (default and fallback) and `pt-PT`. Text lives in `frontend/app/i18n/{language}/{namespace}.json`, one file per namespace and language, so parallel PRs rarely touch the same file.

## Writing text

- Every new string in the interface is added to `en` **and** every other language, by key, in the namespace of its feature (`auth`, `dashboard`, `links`, ...). Text written by an account owner (questions, titles) is not translated. Emails are rendered by Rails and are not covered by this guide until they are localized (I12).
- Keys are flat and in `snake_case`. Placeholders are `{{name}}`. Plurals use i18next suffixes (`_one`, `_other`).
- In components: `const { t } = useTranslation('auth')`. Outside components: `i18n.t('auth:key')`, or `i18n.getFixedT(null, 'auth')` for a typed `t`.
- Keys are typed from the `en` files, so a misspelled key fails `npm run typecheck`.
- Dates and numbers go through `app/i18n/format.ts` (`formatDate`, `formatDateTime`, `formatNumber`, `formatCurrency`), never through a fixed locale such as `en-US`. A component with no `t()` of its own calls `useLocale()` so it re-renders when the language changes.

## Loading

`en` is in the app bundle: it is the fallback and the language the server renders in. The other languages are one chunk (`app/i18n/translations.ts`), fetched only by the visitors who use one of them: before hydration when the cookie or the browser asks for it (`entry.client.tsx`), or when the language switcher picks it. The server loads every language at startup (`entry.server.tsx`), so a server-side `i18n.getFixedT(locale)` (the form's meta description) works for any language.

## The check

`npm test` (also run by the `frontend` job in CI) fails when, for any language other than `en`:

- a namespace file is missing;
- a key exists in one language and not the other (plural suffixes are ignored);
- a `{{placeholder}}` differs;
- an `en` key is not referenced anywhere in the source (as `'key'` or `'ns:key'`).

A namespace whose translated file is `{}` is skipped until it is translated.

## Adding a language

1. Add the tag to `LOCALES` in `app/i18n/locales.ts` and teach `match()` which browser tags map to it.
2. Create `app/i18n/{tag}/` with one JSON file per namespace in `app/i18n/en/` (start with `{}` and fill them in). Nothing to import: `app/i18n/translations.ts` picks the files up. That chunk holds every language but `en`, so with a third language give each language a module of its own.
3. Run `npm test` and `npm run typecheck`. The check picks the new language up from `LOCALES`.
4. Look at the screens in the browser: translations are often longer than English and can clip in narrow buttons.

Legal text (`/privacy`, terms) is only published in a new language after a human review.
